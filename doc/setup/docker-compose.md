# Docker Compose — daloRADIUS Stack

> **⚠️ This document is a reference only.**
> Do NOT follow the manual steps below for a new deployment.
> Instead, run the automated installer which handles everything:
>
> ```bash
> bash setup/install-docker-compose.sh
> ```
>
> The installer performs all steps described here automatically: secrets
> generation, `.env` creation, data directories, TLS certificates (optional),
> MariaDB startup with healthcheck, database and user creation, schema loading
> (idempotent — skips if tables exist), and service startup.
> It also detects re-runs and shows an interactive menu.
>
> **Requirement**: Docker Compose v2.20+ (the `docker compose` plugin, not the
> standalone `docker-compose` v1 binary). The stack uses the `include:`
> directive for modular services, which is not available in v1.

## Architecture

The stack consists of three services, each with its own `docker-compose.yml` under `docker/<service>/`:

```
daloradius/
├── docker-compose.yml                 ← Root orchestrator (includes all 3)
└── docker/
    ├── mariadb/docker-compose.yml      ← MariaDB (database)
    ├── freeradius/docker-compose.yml   ← FreeRADIUS (RADIUS server)
    └── daloradius/docker-compose.yml   ← Web UI (Apache + PHP)
```

### Root orchestrator (`docker-compose.yml`)

The root file is auto-generated by `setup/install-docker-compose.sh`.
Its only job is to include the 3 services via `include:`:

```yaml
include:
  - docker/mariadb/docker-compose.yml
  - docker/freeradius/docker-compose.yml
  - docker/daloradius/docker-compose.yml
```

### Nested includes (by design)

Each service compose file also includes its dependencies:

| File | Includes | Reason |
|------|----------|--------|
| `docker/mariadb/compose.yml` | *(none)* | Base service |
| `docker/freeradius/compose.yml` | `../mariadb/compose.yml` | FreeRADIUS needs the DB |
| `docker/daloradius/compose.yml` | `../mariadb/compose.yml` + `../freeradius/compose.yml` | Web UI needs DB + RADIUS |

This allows running services independently:

```bash
# MariaDB only
docker compose -f docker/mariadb/docker-compose.yml up -d

# FreeRADIUS + MariaDB
docker compose -f docker/freeradius/docker-compose.yml up -d

# Full stack (via standalone file)
docker compose -f docker/daloradius/docker-compose.yml up -d
# Or using the root orchestrator (recommended):
docker compose up -d
```

When using the root orchestrator, Docker Compose **deduplicates** includes:
each service is only instantiated once, even if referenced multiple times.

### `.env` dependency

The root orchestrator and all standalone compose files load variables from `.env`
in the project root directory. This file provides non-sensitive configuration:

```bash
cp .env.example .env
# then edit .env with your values
```

Passwords and secrets are NOT stored in `.env`. They come exclusively from
Docker Secrets (`secrets/db/*` and `secrets/daloradius/*`).

> **Important**: When running standalone compose files from a different directory,
> you must pass the project directory explicitly:
> ```bash
> docker compose --project-directory . -f docker/freeradius/docker-compose.yml up -d
> ```

## Quick start

Run the automated installer from the project root:

```bash
bash setup/install-docker-compose.sh
```

**What the installer does:**

| Step | Action |
|------|--------|
| 0 | Creates `data/mysql`, `data/freeradius`, `data/daloradius`, `logs/freeradius` |
| 1 | Prompts for or auto-generates secrets (`mysql_root_password`, `mysql_password`, `daloradius_client_secret`) |
| 1b | Writes the root `docker-compose.yml` orchestrator with `include:` directives |
| 2 | If `FREERADIUS_SQL_TLS=enabled`, generates self-signed SSL certificates and creates `tls-compose.yml` override |
| 3 | Creates `.env` from `.env.example` with generated secrets |
| 4 | Starts MariaDB and waits for it to be healthy (up to 60s) |
| 5 | Creates the `radius` database and application user |
| 6 | Loads FreeRADIUS and daloRADIUS SQL schemas (skips if tables already exist) |
| 7 | Starts FreeRADIUS and daloRADIUS web containers |

On re-run, the installer detects existing secrets and shows an interactive menu
with options to view config, get manual cleanup steps, or reconfigure from scratch.

## Manual setup

If you prefer to configure everything by hand instead of using the installer:

1. **Create secrets**: Generate random passwords and write them to `secrets/db/mysql_root_password`,
   `secrets/db/mysql_password`, and `secrets/daloradius/daloradius_client_secret`.
   Set permissions to `chmod 600`.

2. **Configure `.env`**: Copy `.env.example` to `.env` and edit the values.

3. **Start MariaDB**: `docker compose up -d radius-mysql`

4. **Create database and user**: Connect to MariaDB and run:
   ```sql
   CREATE DATABASE IF NOT EXISTS radius;
   CREATE USER IF NOT EXISTS 'radius'@'%' IDENTIFIED BY '<password>';
   GRANT ALL PRIVILEGES ON radius.* TO 'radius'@'%';
   FLUSH PRIVILEGES;
   ```

5. **Load schemas**: Import `contrib/db/fr3-mariadb-freeradius.sql` and
   `contrib/db/mariadb-daloradius.sql` into the `radius` database.

6. **Start the stack**: `docker compose up -d`

See `setup/install-docker-compose.sh` for the full automated workflow.

## Environment variables (`.env`)

| Variable | Default | Description |
|----------|---------|-------------|
| `MYSQL_HOST` | `radius-mysql` | MariaDB hostname |
| `MYSQL_PORT` | `3306` | MariaDB internal port |
| `MYSQL_HOST_PORT` | `3306` | MariaDB host port (change to avoid conflicts) |
| `MYSQL_DATABASE` | `radius` | Database name |
| `MYSQL_USER` | `radius` | Application DB user |
| `FREERADIUS_SQL_TLS` | `disabled` | TLS for SQL connection (`disabled`, `enabled`, `require`) |
| `DALORADIUS_OPERATORS_BIND` | `0.0.0.0:8000` | Bind address for the operators admin panel |
| `TZ` | `Europe/Vienna` | Timezone |
| `MYSQL_HEALTH_START_PERIOD` | `10m` | Grace period for MariaDB healthcheck on first start |
| `MYSQL_BIND_ADDRESS` | *(empty)* | Bind address for port 3306 (empty = Docker network only) |
| `MAIL_SMTPADDR` | `127.0.0.1` | SMTP server for email notifications |
| `MAIL_PORT` | `25` | SMTP port |
| `MAIL_FROM` | `root@...` | Sender email address |
| `PASSWORD_MIN_LENGTH` | *(empty)* | Min password length for operators |
| `PASSWORD_MAX_LENGTH` | *(empty)* | Max password length for operators |

> **Passwords are NOT stored in `.env`**. They come exclusively from Docker
> Secrets (`secrets/db/*` and `secrets/daloradius/*`). The init scripts read
> `MYSQL_PASSWORD` and `DEFAULT_CLIENT_SECRET` from environment variables as
> a fallback before secrets are mounted, but the source of truth is the
> secret files.

## Secrets

All credentials are stored as files under `secrets/` with `chmod 600`:

```
secrets/
├── db/
│   ├── mysql_root_password      ← MariaDB root password
│   ├── mysql_password           ← Application DB password
│   ├── ca.key.pem               ← TLS CA private key
│   ├── mysql_ca.pem             ← TLS CA certificate
│   ├── mysql_server.key.pem     ← TLS server private key
│   ├── mysql_server.csr         ← TLS CSR
│   └── mysql_server.pem         ← TLS server certificate
└── daloradius/
    └── daloradius_client_secret ← RADIUS shared secret for the default client
```

These are mounted as Docker Secrets (`/run/secrets/*`) in each container.

## TLS (SQL connection)

See `doc/setup/ssl-config.md` for TLS configuration between FreeRADIUS and MariaDB.

> **⚠️ These are SQL connection certificates, NOT the same as EAP/WiFi certificates below.**
> SQL TLS certs are stored in `secrets/db/` and only protect the link between FreeRADIUS and the database.
> They are never presented to network clients (WiFi access points, switches, VPNs).

## EAP/TLS Certificates (WiFi & wired 802.1X authentication)

FreeRADIUS uses TLS certificates for EAP authentication (PEAP, TTLS, EAP-TLS). These are the
certificates presented to **network clients** — WiFi access points, wired switches using
802.1X, VPN concentrators, and any other NAS device that authenticates via EAP.

> **⚠️ These are NOT the same as the SQL TLS certificates above.** EAP certificates
> are stored inside the FreeRADIUS container and authenticate users on your network.
> SQL TLS certificates only encrypt the database connection.

The container handles EAP certificates automatically:

### Auto-generated certificates (default — development only)

On first start (or if certificates are missing/expired), `init-freeradius.sh` generates
self-signed certificates with **10 years validity** using FreeRADIUS built-in Makefile.

> **⚠️ Not recommended for production.** Self-signed certificates will trigger
> security warnings on client devices and may not be accepted by all 802.1X
> supplicants. Use externally-signed certificates for production deployments.

### External certificates (production — Let's Encrypt, enterprise CA, etc.)

To use your own certificates signed by a trusted Certificate Authority:

1. Mount them via volumes in `docker/freeradius/docker-compose.yml` (already configured):

   ```yaml
   volumes:
     - ../../docker/freeradius/ssl/cert_ext:/etc/freeradius/certs/cert_ext
     - ../../docker/freeradius/ssl/private_ext:/etc/freeradius/certs/private_ext
   ```

2. Place your certificate files:

   | Host path | Required file |
   |-----------|--------------|
   | `docker/freeradius/ssl/cert_ext/server.pem` | Server certificate + intermediate chain |
   | `docker/freeradius/ssl/cert_ext/ca.pem` | CA certificate (trusted root) |
   | `docker/freeradius/ssl/private_ext/server.key` | Private key |

3. Restart the container:

   ```bash
   docker compose -f docker/freeradius/docker-compose.yml restart radius
   ```

The init script detects external certificates automatically and configures EAP to use them.
External certificates are **never overwritten** by the auto-generation process.

### Certificate usage summary

Two independent TLS systems exist in this stack. **They are NOT interchangeable.**

| | **EAP/TLS** (WiFi / 802.1X) | **SQL TLS** (DB connection) |
|---|---|---|
| **What it does** | Authenticates the RADIUS server to network clients (WiFi APs, switches, VPNs) so they trust it before sending user credentials. | Encrypts the connection between FreeRADIUS and MariaDB. Never seen by network clients. |
| **Where files live inside the container** | `/etc/freeradius/certs/` | Mounted as secrets: `/run/secrets/mysql_*.pem` |
| **Where you put them on the host** | **Auto-generated**: nowhere — they are created inside the container and lost on container delete.<br>**External (production)**: `docker/freeradius/ssl/cert_ext/` + `docker/freeradius/ssl/private_ext/` → mounted as bind volumes. | `secrets/db/mysql_*.pem` → mounted as Docker Secrets. |
| **How to provide them** | Default: nothing to do — FreeRADIUS generates them on first start.<br>Production: place `.pem`/`.key` files on the host and restart the container. | Set `FREERADIUS_SQL_TLS=enabled|require` in `.env` and run the installer, or place files manually. |
| **What happens if missing** | FreeRADIUS auto-generates self-signed ones. | SQL connection falls back to plain (no encryption). |

**Key takeaway**: EAP certificates live **inside the FreeRADIUS container** (`/etc/freeradius/certs/`). They are either auto-generated there, or mounted from your host into the `cert_ext/` and `private_ext/` subdirectories. You never interact with the container's internal paths directly — you either let the container create them, or place files on your host and Docker maps them in.
