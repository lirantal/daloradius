# UNIT-025 — création d'opérateurs et de leurs ACL

Portée : `DB-OPADMIN-004`, `app/operators/config-operators-new.php`. La page conserve sa session, son contrôle `config_operators_new`, le formulaire ACL et la règle d'identité `local` / `ldap` de `operator_identity.php`. Le contrôle d'autorisation et l'affichage du formulaire ACL effectuent encore des **lectures PEAR indépendantes**. Le chemin de création, lui, utilise une connexion PDO liée à la location de la session ; aucun bloc de mutation n'est partagé entre PEAR et PDO.

Avant la connexion d'écriture, les champs sont vérifiés comme scalaires, le mot de passe local est haché par la règle existante et les tailles du schéma `operators` sont contrôlées, plutôt que tronquées par le mode SQL permissif. Le retrait historique de `%` dans le nom est conservé, pour rester compatible avec l'édition d'opérateur existante. Chaque ACL envoyée doit correspondre à un fichier du catalogue `operators_acl_files` et avoir une valeur `0` ou `1` ; un formulaire sans ACL est refusé, au lieu de créer un compte orphelin. Le mot de passe LDAP reste SQL `NULL`, avec un identifiant externe éventuellement présent.

La connexion PDO précontrôle les trois tables InnoDB. Sous un verrou consultatif par base, elle vérifie le nom existant et les ACL du catalogue sur le **même handle transactionnel**, insère l'identité, récupère `lastInsertId()`, insère tous les accès, puis commit. Toute erreur (en particulier un échec sur une ACL tardive) annule l'identité et les ACL précédentes. L'acquisition du verrou évite que deux appels à cette page créent simultanément le même nom, malgré l'absence d'index unique `operators.username`. **Elle ne coordonne pas les écrivains externes** qui ne prennent pas le même verrou et ne remplace pas une contrainte d'unicité au niveau du schéma. Une collision sur `external_id` est rejetée par l'index unique existant et annule la transaction.

Aucun mot de passe, hash, valeur liée ou erreur PDO brute n'est écrit dans les messages et traces de cette page. Les liens de résultat encodent le nom pour le paramètre d'URL et pour le HTML. Les modifications des ACL par `config-operators-edit.php` restent dans une autre unité ; leur logique PEAR n'est pas incluse dans cette migration.

## Validation isolée

`python3 tests/operator_create_http.py` exerce le formulaire HTTP réel avec PHP et MariaDB 11.8 sur un réseau Docker interne jetable ; `OPERATOR_CREATE_BASELINE=1 python3 tests/operator_create_http.py` substitue seulement la page du commit pré-UNIT `3e727673fdbdc0de793cfa820cd13b1c3d7f22bd`. Comparer les instantanés `NORMAL_STATE=` (sans mot de passe, hash, identifiant de session ou date/ID généré). Les deux chemins testent local et LDAP, des champs Unicode/quotes, le hash vérifié sans l'exposer, l'authentification HTTP réelle du nouvel opérateur et sa permission, le nom dupliqué, le contrôle ACL/CSRF et le refus sans session. Le candidat teste aussi des ACL inconnues/malformées, des champs non scalaires ou surdimensionnés, un formulaire sans ACL, un trigger en échec sur la **deuxième** ACL, un identifiant externe dupliqué, la table non transactionnelle, et deux créations concurrentes du même nom ; l'état entier des identités et des ACL est comparé avant/après les refus. Aucun compte ou service de production n'est sollicité.

Les conteneurs et données jetables sont supprimés par le test. Cette validation n'atteste pas d'un déploiement en production, ni d'une unicité inter-applications sur un schéma sans index unique.
