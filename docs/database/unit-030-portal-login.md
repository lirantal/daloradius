# UNIT-030 — Authentification du portail utilisateur

`app/users/dologin.php` lit désormais `userinfo` via PDO, sur la localisation déjà portée par la session (ou `default`). Le nom de table provient exclusivement de `CONFIG_DB_TBL_DALOUSERINFO` et est validé comme identifiant SQL ; toutes les valeurs sont liées. Une table non transactionnelle est refusée avant la vérification. Le parcours conserve les contrôles CSRF, la langue et son cookie, les messages et redirections, ainsi que les règles existantes de mot de passe du portail. `app/users/login.php`, ses messages et les autres opérations du portail restent sur PEAR.

Le mot de passe historique en clair est rehashé à la première connexion par un `UPDATE` conditionnel sur l'ancien contenu, l'ID, le nom et l'activation du portail. Une modification concurrente ne peut donc pas être écrasée. Le compte est ensuite relu sous verrou dans une transaction PDO ; le nom, l'activation et le mot de passe vérifié sont recontrôlés avant le commit et l'ouverture de la session. Un échec de rehash, de vérification finale ou de base de données refuse la connexion sans exposer les valeurs SQL. Le rehash est distinct de la transaction de vérification finale : un échec ultérieur peut laisser le hash renforcé sans ouvrir de session. Une session déjà ouverte avant la révocation d'un compte reste soumise aux contrôles existants.

Validation : `PORTAL_LOGIN_BASELINE=1 PYTHONDONTWRITEBYTECODE=1 python3 tests/portal_login_http.py` puis `PYTHONDONTWRITEBYTECODE=1 python3 tests/portal_login_http.py`, sur deux installations HTTP/PHP/MariaDB jetables équivalentes. Les parcours comparés incluent hash courant, ancien mot de passe en clair, valeur `0`, erreur de mot de passe, compte absent/désactivé/sans mot de passe, doublon de nom et nom Unicode avec apostrophe. Le candidat teste aussi les champs malformés, la concurrence sur le rehash, le changement de mot de passe ou la désactivation avant la vérification finale, une erreur SQL injectée et le rejet de MyISAM. Le test PHP statique du stockage des mots de passe et ses tests fonctionnels restent exécutables. Ces tests ne sont ni une validation en production, ni un déploiement. **Aucune clé, aucun mot de passe, jeton, secret ou identifiant de connexion ne doit être conservé.**
