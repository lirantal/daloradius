# UNIT-031 — Changement du mot de passe du portail utilisateur

`app/users/pref-portal-password-edit.php` consulte le hash du compte et modifie le mot de passe via PDO sur la localisation de session existante. Le nom de table configuré est validé comme identifiant ; l'identité, le nouveau hash et l'ancien hash sont liés. La comparaison avec l'ancien hash est byte-à-byte sur MySQL/MariaDB et conserve la distinction entre une ligne modifiée, un conflit (`0`) et une erreur SQL. Le code ne propage ni erreur PDO ni valeur de mot de passe dans la réponse ou dans ses journaux d'erreur. L'écriture conditionnelle étant un seul `UPDATE` atomique, elle ne répartit aucune transaction sur les deux connexions. Le contrôle de session, le CSRF, le formulaire, les textes de réponse et la journalisation d'actions sont conservés. Les autres chemins du portail et les composants partagés non migrés peuvent toujours utiliser PEAR.

Validation : `PORTAL_CHANGE_TEST=1 PORTAL_CHANGE_BASELINE=1 PYTHONDONTWRITEBYTECODE=1 python3 tests/portal_login_http.py` puis `PORTAL_CHANGE_TEST=1 PYTHONDONTWRITEBYTECODE=1 python3 tests/portal_login_http.py`. Le fixture compare les parcours HTTP/PHP/MariaDB jetables PEAR/PDO : modification, ancien mot de passe incorrect, confirmation erronée, entrée vide, nom Unicode/apostrophe, mot de passe `0` et CSRF invalide ; il contrôle le hash stocké sans l'afficher. Sur PDO il vérifie aussi les champs tableau, l'échec SQL injecté et le `UPDATE` conditionnel après un changement concurrent sur une autre connexion. Tests ciblés : `tests/portal-password.test.php`, `tests/portal-password-storage.test.php`, vérification de syntaxe PHP et `git diff --check`. Ni production ni charge réelle n'ont été testées. **Aucune clé, aucun mot de passe, jeton, secret ou identifiant de connexion ne doit être conservé.**
