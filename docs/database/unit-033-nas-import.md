# UNIT-033 — Import NAS transactionnel via PDO

L'aperçu et la confirmation de `app/operators/mng-rad-nas-import.php` utilisent PDO. La table NAS configurée est validée comme identifiant SQL et les valeurs, y compris les champs binaires du format JSON v2, sont liées. La confirmation valide l'aperçu, acquiert sur la même connexion le verrou consultatif `daloradius:nas:*` déjà utilisé par les pages NAS PEAR, refuse une table non InnoDB, ouvre une transaction, relit les noms, vérifie chaque nom et chaque insertion, puis commit toutes les nouvelles entrées ou les annule toutes. Le verrou est libéré après commit ou rollback ; une libération dont l'échec survient après le commit ne transforme pas une réussite en échec. La connexion n'est pas persistante. Les doublons apparus après l'aperçu sont ignorés, sans remplacer les NAS existants. Les exceptions SQL et les secrets NAS ne sont pas affichés ni journalisés.

Les helpers de verrou et de classification des doublons dans `nasImportExport.php` distinguent désormais PDO et PEAR ; les pages NAS de création, édition et suppression ainsi que l'export restent sur PEAR. Les lectures d'ACL de l'import restent également sur PEAR. L'absence de contrainte unique universelle sur `nasname` laisse une possibilité de course avec un écrivain externe qui ne prend pas le même verrou ; le contrôle applicatif ne prétend pas éliminer cette course.

Validation : `NAS_IMPORT_BASELINE=1 PYTHONDONTWRITEBYTECODE=1 python3 tests/nas_import_http.py` et `PYTHONDONTWRITEBYTECODE=1 python3 tests/nas_import_http.py` sur HTTP/PHP/MariaDB jetables. Comparaison : aperçu, ajout, doublon existant ou apparu après l'aperçu, entrée invalide, absence de fuite dans la réponse, jeton à usage unique, et création NAS via le chemin PEAR partagé. Le candidat couvre aussi les jetons malformés, une erreur sur la deuxième insertion avec rollback et libération du verrou, le refus de MyISAM, un nom binaire v2 et l'attente du verrou déjà détenu sur une autre connexion. Ces essais ne valident ni un redémarrage FreeRADIUS ni la production. **Aucune clé, aucun mot de passe, jeton, secret ou identifiant de connexion ne doit être conservé.**
